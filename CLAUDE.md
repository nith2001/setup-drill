# Setup Drill

Personal POC for practicing day-trading setups on replayed 1-minute charts. Each rep is a random historical day (ticker/date hidden); about half the charts contain no valid setup. Grading is on the **decision** (take vs. pass) and execution, not P&L. User-facing docs are in `README.md`.

## Ground rules
- Goal: grow it step by step into something solid that the owner uses to learn trading; the owner is also learning to build it. Possible SaaS later, not a priority now.
- Prefer incremental, well-structured changes over big rewrites. Don't over-engineer; use quick spikes to de-risk.
- Keep it free/cheap and personal-use first.
- Never commit `.env`, `data/` (Alpaca data is not redistributable) or `journal/` (the owner's personal trade diary). All gitignored.
- Don't write test reps into the owner's real `journal/journal.json`; if a browser test creates entries, delete them via `DELETE /api/journal/<id>`.

## Commands
- `npm run dev` (or `npm start`): Vite dev server on :5173. The `server/dataSync.ts` plugin reads keys from `.env`, syncs random Alpaca days into `data/days.json` in the background (incremental, saves every 10 dates), and serves `/api/data` + `/api/status`. The browser never calls Alpaca. Disabled under Vitest.
- `npm test` (Vitest), `npm run typecheck`, `npm run build`, `npm run audit` (valid pool + textbook-trade results per setup on `data/days.json`; `AUDIT_SETUPS=id,id`, `AUDIT_BIAS=legacy`).
- Chart reports: the ⚑ Report button (any chart) appends to `reports/reports.jsonl` (gitignored) via `POST /api/reports` (`server/reports.ts`): owner's reasons + note, sym/date, mode, rule candles, and what the rule saw (valid/dir, trigger, marks with candle times, lines, target, ideal trade). `npm run reports` lists them and re-runs the current rule on each chart (then vs now). When the owner says they reported a chart, start there.
- Sync knobs in `.env`: `SYNC_DAYS` (100 random dates × all symbols), `SYNC_YEARS` (3), `SYNC_SYMBOLS`, `SYNC_INDEX_SYMBOLS` (SPY,QQQ), `SYNC_INDEX_DAYS` (500 consecutive recent days). Changing symbols adds, never resets. Sync also backfills `ctx` (daily) and `ctx.prev5` (prior session 5-min closes) for cached days missing them.
- Alpaca auth needs BOTH Key ID and Secret (key-only gets 401). History comes from data.alpaca.markets, not paper-api. Free plan 403s on SIP data from the last 15 min, so request end times stay 20 min behind now.

## Layout
- `src/core/`: pure logic, no DOM. `types.ts`, `day.ts` (time, VWAP, relVol), `candles.ts` (TF type, multi-day candle building, History), `overlays.ts` (user indicator config + computation), `indicators.ts`, `fills.ts`, `grading.ts`, `demo.ts`.
- `src/setups/`: one file per setup exporting a `SetupDef` (label, rule text, `evaluate`, `preset` = the exact indicators its drills show). Teaching text per setup lives in `lessons.ts` (`steps` keyed by mark text). Thresholds are constants at the top of each file. Register in `index.ts`.
- `src/engine/replay.ts`: `Replay` class = one rep (clock, stepping, play, orders, fills, restart, grading). Emits changes; React reads via `useSyncExternalStore`.
- `src/data/alpaca.ts`: Alpaca client, session/bar conversion, `fetchHistory` (Node-side).
- `src/ui/`: React. `App.tsx` (boot, data sync, rep lifecycle), `Home.tsx`, `Session.tsx` (top bar, side panel, result sheet, keyboard), `ChartPane.tsx` (declarative lines/markers), `ChartOverlay.tsx` (SVG layer over the price pane: SL/TP bracket + drawings, all drag handling), `OrderTicket.tsx` (ticket + position card), `AccountPanel.tsx` (bottom panel), `drawings.ts`, `IndicatorPanel.tsx`, `chart/ChartView.ts` (imperative Lightweight Charts wrapper, blind axis labels), `state.ts` (settings, history, pools, toasts), `data.ts` (API calls).
- `src/core/journal.ts`: JournalEntry/JournalTrade types, `summarize`, `equityCurve`, `streakDays`, `tagCounts`, `toCsv`.
- `server/journal.ts`: journal file store + Vite plugin: `GET/POST /api/journal`, `PATCH/DELETE /api/journal/<id>`, atomic writes to `journal/journal.json`.
- UI shell: `App.tsx` tabs Practice (`Home.tsx`) / Journal (`Journal.tsx`, also exports `ReviewBox` used on the grade sheet) / Settings (`Settings.tsx`). `journalStore.ts` = client store (falls back to localStorage, migrates legacy `drill.history`). Note: macOS is case-insensitive, so don't name modules `journal.ts` next to `Journal.tsx`.
- `server/dataSync.ts`: Vite plugin. Background sync of rep days into `data/days.json`; `/api/history` fetches+caches per sym/date history in `data/history/`.
- Tests: `tests/*.test.ts` (Vitest). Per-setup checks run for every registered setup automatically.
- TypeScript pinned to 5.9: TS 7.0.2 with `jsx: react-jsx` mis-parses `<const T>` generics in @types/node.

## Design notes
- Day shape: `{sym, date, pc, ctx?, o[], h[], l[], c[], v[]}`; `ctx` = `{pdh, pdl, pdc, sma50, sma200}` from daily bars strictly before the date (sync backfills it into old caches; demo data synthesizes it), one bar/min from 09:30 ET, RTH only; missing minutes filled flat with 0 volume. Chart time = ET wall-clock treated as UTC.
- Evaluators return `null` (day lacks context) or `{valid, dir, trigIdx, refStop, startIdx, windowEnd, why, marks?, lines?}`. `marks`/`lines` are teaching annotations drawn once the rep is done. `refStop` must be at or beyond the trigger candle's extreme (tested). Each setup's pool is split valid/no-trade; reps sample 50/50. A third (`QUIET_SHARE`, state.ts) of no-trade picks are **quiet charts** (owner asked 2026-11-17): `quietWindow` (setups/index.ts) picks a 60–120 min stretch where the setup never starts (no event of any kind overlaps it or the 18-candle lead-in; checked against the whole day's events). Open-tied setups (`openOnly`: orb, orbBreak, gap) have none. Rep runs `startIdx` → `windowEnd` (rule deadline + 5 bars). One event per day per setup.
- Flat: chart shows no bracket; the ticket holds settings (risk $/%, R:R, TP on/off) and Buy/Sell buttons. SL/TP lines appear only after entry, on the traded side.
- History: daily (~300), 5-min (40 sessions), 1-min (previous `M1_DAYS`=2 sessions). Cached files without `m1` are refetched.
- Live P&L view (`order.pnlView`, default ticks; `src/ui/pnl.ts`, tick = $0.01): while in a trade the UI shows ticks/R/$ as chosen; Balance changes only on close, Equity shown only in $ view.
- Orders: market only. `Replay.plan` is what the ticket would send (side, entry, stop, target, qty, error); qty = floor(risk$ / per-share risk), capped at 4× balance. Auto stop = 5-bar extreme but at least 0.15% away. Trades carry `qty` and `pnl`; grading stays in R.
- Real-time replay: each 1-min bar plays a simulated path (`src/core/path.ts`: TICKS=120, seeded by sym/date/idx, open → high/low in plausible order → close, 1-cent steps, exact OHLC). `Replay.sub` = tick within the forming bar cur+1 (-1 = none); `rep.forming` is merged into the chart's current candle by `buildCandles(…, forming)`. Speed = multiple of real time (`SPEEDS` 1…300; drills start at 1×, examples/tutorials 60×; +/− keys). `autoSlow` (Settings, default on) drops to 1× on entry. `advanceTo`/step buttons play every tick instantly so fills stay path-based.
- Fills (replay): on the tick path. Market orders at the current tick + slippage (max $0.01 / 0.02%). Stops/targets fill when a tick crosses them (at the level; at the tick price if a bar's open gaps through). Stop required before entry. `entryIdx` = last completed bar (so entering while the trigger candle forms grades as early); `entryBar` = bar the fill happened in (display). `idealTrade`/`simulateTrade` still use whole bars (`evalBar`, stop wins ties).
- Decision grade: no-trade chart → pass 100, any trade ≤20. Valid chart → Decision 50 (right dir within 3 bars) + Timing (15 − 5×bars late) + Stop 20/10/5 (good/too wide/too tight vs. trigger candle & `refStop`) + Discipline 15. Missed valid ≈ 15. >3 bars late = "Chased".
- Free play is scored on R, capture, heat, discipline. Free play starts at a random minute (open → 2h before close) unless Settings says "At the open", and always runs to the close.
- Example mode (`Replay.example`): a chart shown played out, no trading, never journaled. Valid examples prefer charts where `idealTrade` (enter trigger close, stop `refStop`, setup target or 2R) hit target within 90 min, and run until it resolves; no-trade examples come from the `none` pool. `pickExample(id, 'win' | 'loss' | 'none')`: 'loss' = valid charts whose textbook trade was stopped out. Drills never filter on outcome. `gradeDecision` adds a note when the textbook trade on a valid chart lost (taken: "that's fine"; missed: "still valid").
- Model for S/R and indicator setups (owner's rule): prove → retest → trigger candle. S/R levels need two touches (`twoTouchLevel`); ema (touch 1 bounce → touch 2) and vwap (bias side → touch 1 bounce → touch 2) need the indicator proven once. Swing points: `isSwing` with `swingK` (2 on 5-min, 3 on 1-min).
- Targets: `ValidEval.target {price, why}` when structure gives one (srReject: bounce extreme after touch 1; rangeFade: just inside the other edge; flag: measured move). Those skip trades under `MIN_RR` (1.5). Everything else = fixed 2R (`idealTrade` falls back). 1-2-3 measured move averaged ~1R on real data and flip breakout-high targets killed most flips, so both use 2R.
- Rule candles: `settings.ruleTf` (default 5). `evaluateAll` aggregates the day with `barsOf(day, m)` (cached, carries `warm` = ctx.prev5 so `indicators()` start warm), runs the setup on candles, and maps results to 1-min indices (trigger = the candle's closing minute; `ev.barMin` records the size). Setups never assume 1-min: minute windows go through `bars(day, min)`, times through `at(day, i)`, size thresholds are multiples of `avgRange` (average candle). Grading: "within 3 bars" = 3×barMin minutes; trigger-candle extreme spans barMin minutes. Replay `barMin` sets the default stop (last 5 candles).
- Several events per day: `evaluateAll` re-runs with `opts.from` = previous windowEnd+1 (max 4); every setup's scan loop starts at `from(o, min)`. ORB / Gap return null when `from` > 0.
- Universe: `settings.universe` = index (SPY/QQQ, `src/core/universe.ts`) / stocks / all; pools rebuilt by `setData` on change.
- Setup drills open on the rule's candle size showing exactly their preset indicators (`presetConfig`); changes are remembered per setup (`drill.ind2.<id>` in localStorage, reset button in the panel). Free play uses the general `drill.indicators2`. Owner's rule: VWAP and prior-day lines are off unless a setup's rule uses them (VWAP: Gap, VWAP Bounce, Range Fade; prior day + daily SMA: Gap (prior day only), S/R Retest, S/R Flip); otherwise opt-in.
- Tutorial (`Replay.tutorial`, implies `example`: no trading, never journaled): a valid example started ~6 candles before the first mark. `TutorialCard` steps intro → each mark → trigger → outcome → mistakes; `rep.pauseAt` stops playback on each step's bar. Marks/lines (`lines[].idx` = when the level is known) and the ideal entry/stop/target appear only once replay reaches them. The chart keeps the last 60 candles in view.
- Trigger candle (owner's model, 2026-11-16): `triggerCandle(day, k, dir)` in util = engulfing (prior candle opposite colour, body covered) or hammer / shooting star (wick ≥ 2× body and ≥ half the range, close in the trend third). Used by ORB, S/R Retest, S/R Flip, VWAP, EMA, Range Fade, MACD, RSI (window includes the test candle itself). 1-2-3 keeps engulfing only; Gap keeps its breakout close; Flag uses `triggerCandle` or a strong candle on the break.
- S/R Retest stop (owner report 2026-11-17, SPY 2026-05-26): a test can turn ~0.05% above the line (`tolAt`), so the old stop under the test wick sat inside the zone (0.25 stop, a fake 4R). Now `SRR.BEYOND` 0.1: stop = beyond the level by 0.1 avg candle, or the wick if further. Audit: 315 trades 27% −0.01R → 277 trades 32% +0.03R. Same report: the 'third test' stopped 0.35 short of the line (0.05%-of-price tolerance = ±0.37 on SPY, ~0.7 candle). `TOL.pct` (util) now 0.0002 so touch tolerance comes from average candles; audit change was noise (srReject 279 → 236, +0.03 → −0.01R; srFlip 100 → 94, −0.06 → −0.04R), chosen for correctness.
- S/R levels: `twoTouchLevel` = two swing lows/highs at a common price (zone 0.3 avg candles, ≥6 candles apart, each bounces) or the prior day low/high plus one swing. S/R Retest trades touch 3; S/R Flip breaks it and trades the retest. Marks: touch 1/2/3, break, retest.
- ORB Breakout (`orbBreak`, 2026-11-16): first close outside the opening range within 90 min; the breakout candle is the trigger (body ≥60% of range closing in the top quarter, or engulfing) with time-of-day RVOL ≥1.0 (`ORB_BREAK.volMin`; 1.0 beat 1.2/1.5 on real data: SPY/QQQ 53 trades +0.41R, all 210 +0.18R) (`rvolTod`, baseline `ctx.vol5` = per-5-min-slot volume avg over prior 20 sessions, backfilled with prev5 in `backfillPrev5`; falls back to `relVol`). ORB Retest now uses `rvolTod` too.
- ORB = "ORB Retest": breakout on volume → away 1 avg candle → retest of the range edge within 60 min → trigger; close back inside = failed breakout. Rare (~1.4% of days; demo test allows ≥1 valid).
- Pools, all symbols, 5-min (`npm run audit`, after the bias rework + relaxing small pools 2026-11-16): orbBreak 290 +0.16R, orb 75 +0.15R, gap 90 +0.24R, vwap 177 0R, trend123 326 +0.03R, flag 131 −0.09R, srReject 277 +0.03R (stop beyond the level, see below), srFlip 100 −0.06R, rangeFade 113 +0.41R, ema 119 +0.03R, macd 415 −0.08R, rsi 175 +0.09R. Owner wants ≥ ~70 valid per setup. Flag (`FLAG`: candle trigger, bias-direction scan, time-of-day volume) and S/R Flip (`FLIP`: prior-day + older daily levels via `DAY_LEVELS`, retest zone 0.75, fakeout 0.5) were relaxed from 52 / 20 at a small cost (−0.06 → −0.09R; +0.03 → −0.06R); no flag variant was positive. Tuning knobs are exported objects per setup (`ORB`, `GAP`, `RF`, `SRR`, `FLAG`, `FLIP`, `T123`); `scripts/sweep.check.ts` (`CHECK=sweep`) has the sweep helper.
- Bias (`src/core/bias.ts`, owner's model, reworked 2026-11-16): week trend from `ctx.h4` (last 7 sessions as 4-hour candles 09:30–13:30 / 13:30–16:00, backfilled in `backfillPrev5`): second half of the last 10 candles vs the first: HH+HL = up, LH+LL = down, else sideways (`kind: 'range'`); an up week that closed in its bottom 40% = sideways. Older levels override (`testedLevels` on `ctx.daily`, 60 daily candles from `dayCtx`): ≥2 daily swings within `BIAS.zone` 0.75 ADR, older than the week; the week's extreme within 0.5 ADR and the last close ≥0.25 ADR back = rejected (bias flips); still close = `wait`. Knobs in `BIAS`. Days without h4 fall back to the old month+week rule on `ctx.closes`. `biasAllows(bias, dir, mode, style)`: setups with `style: 'range'` (rangeFade, srReject) trade both ways on a range bias; trend setups pass on range/wait. Sweep (all setups, 5-min): old month+week 1682 trades +0.06R; new 2412–2437 trades +0.04–0.06R (noise-level differences). Owner's SMCI 2024-05-20 EMA loss: old said long, new says short (rejected at older resistance 94.54, Apr 11 + Apr 30).
- 1-2-3 (label "1-2-3 Pattern"): bias + valid 1-2-3 + trigger candle (engulfing, hammer or strong candle) closing beyond 2 within `T123.wait` 3 candles. No VWAP (classic Joe Ross has none). Knobs live in `T123` (trend123.ts). After the bias rework, `scanBias` off did better (326, +0.03R) than on (571, −0.02R). Owner asked for more trades (2026-11-16); sweep on 5-min real data: engulfing-only + 3-candle pullback = 49 valid (all symbols); chosen = candle trigger, leg ≥ 2 avg candles, pullback ≥ 2 candles and ≥ 25%, strict bias, scan only the bias direction (`scanBias`) → 421 valid, 46% win, +0.09R (SPY/QQQ 154, +0.18R). Edge mostly from 2024; 2025+ ~0R. Tested and rejected: entry at point 3 on a reversal candle (~−0.05R, 31% win), lenient/week/no bias (worse), optional confluences (20 EMA, VWAP, volume: no gain), measured-move target (worse).
- Universe default 'all' (owner asked 2026-11-16; one-time switch from a saved 'index' via `drill.universeAll`).
- Chart framing: re-frames only on timeframe change, history load, or Restart (`rep.restarts`); stepping keeps the user's zoom.
- Drill start: each setup's `startIdx` is just after the pattern's context is formed (1-2-3: point 2 confirmed; S/R and EMA/VWAP: touch 1 proven). Since 2026-11-17 drills start a random `DRILL_LEAD` 3–18 candles (owner picked) before that (App.tsx), same for valid and no-trade charts, so the trigger isn't on the first candles (before: ~half of ORB Breakout / Gap reps triggered within 2 candles). Marks before the start are explained by `preStartNote`.
- R: trade R and journal R are against the stop at entry (`stop0`/`pos.risk`); widening a stop shows up as a loss > 1R on purpose (owner's TSLA 2025-01-21: −2.64R). Since 2026-11-17 (owner asked for one ratio): the chart's entry pill carries the only R:R (target vs the current stop, `rrRatio` in pnl.ts; moves with either line); SL/TP pills show distance only. The position card's `RiskReward` box shows R:R, 1R (one contract's risk at entry), size, and risk now when the stop moved. **Contracts** (`order.contracts`, stepper on the ticket, reset to 1 every rep by `loadOrder`, max `MAX_CONTRACTS`): one contract = the risk-sized share count (`unitQty`); R = $ ÷ one contract's risk (`rPerShare`), so 2 contracts stopped = −2R. Drawings: hline, trend, rect (box, Alt+B), drawn under the bracket so they never block SL/TP drags.
- Textbook trade: finished drills (valid charts) and examples once the trigger closes show `rep.ideal` as entry/stop/target price lines plus a position box in `ChartOverlay` (trigger candle → exit), and the result sheet has a "textbook trade" card (`TextbookTrade`, shared with `ExampleCard`).
- `ChartView.timeToX` interpolates itself: Lightweight Charts' `logicalToCoordinate` returns 0 for fractional indices. `snap` = centre of the containing candle.
- Chart panning: Lightweight Charts ignores vertical drags while the price axis auto-scales. `ChartView` switches auto-scale off at mouse-down in the price pane (capture phase, before the chart's handler) and back on at mouse-up if the drag stayed horizontal (<4px vertical), like TradingView. The **Auto** button (bottom-right of the pane) or double-clicking the price axis re-enables it; restarts/timeframe changes reset it.
- Rep history/stats in `journal/journal.json` (one entry per chart: only its first finished run; `Replay.journaled` stops restarts from being saved, and `loadJournal` deletes old restart entries via `restartDupes`). `attempt` still increments after Restart. UI prefs in `localStorage`. Market data in `data/days.json`.

## Known limitations (accepted for POC)
- Rule indicators warm up with one prior session (5-min); the chart warms up across more sessions, so very early values can differ slightly. 1-min rules have no warmup.
- Rule thresholds are defaults, not the owner's playbook — expect tuning.
- Demo data skews ORB heavily valid (~315 vs 45); 50/50 sampling compensates.
